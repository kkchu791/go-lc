### Part 2: only the path compression heuristic?
It's still O(m), because nothing depends on rank to make it faster.

LINK without rank is still O(1).
Each FIND-SET still has at most 2 uncompressed nodes on its path (the root and its child), so O(1) per call.
Since all LINKs come first, a compressed node points to its root forever, so each node is compressed at most once: at most n ≤ m total.
