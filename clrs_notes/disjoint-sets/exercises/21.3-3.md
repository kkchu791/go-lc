Goal: You are trying to construct a worst-case sequence that forces FIND-SET to take O(logn) time every single time by building a deep binary tree w/o path-compression.

Sequence of m MAKE-SET, UNION and FIND-SET, n of which are MAKE-SET

horse shoe symbol(mlgn) when we use union by rank.

I mean we know alread in the book, "Alone, union by rank yields a running time of O(mlgn).

Prove the asymptotic upper bound by 

Maximum Tree Height
    rank[x] <= lg[n]

Rank equals tree heigh when path compression isn't used,
maximum heigh of any tree is O(logn) (if input doubles, work goes up just by one step)

Ranks only double when 2 trees of equal size merge, so a tree can't get taller than log^2(n)

### Implementation
//Phase 1: Create n singleton sets
for i = 1 to n
    MAKE-SET(x[i])

// Phase 2: Build a full tree of height log^2(n).
Stride - the step size between element in a loop or array.

for stride = 1, 2, 4, ...., n/2
    for j = 1 to n-stride by (2 * stride)
        UNION(x[j], x[j+stride])

// Phase 3: Repeatedly query the deepest node
for i = 1 to m
    FIND-SET(x[deepest_leaf])

Why this seq. works for worst-case O(mlogn) lower bound:
 * When 2 trees w/ same rank union, one of those trees rank goes up
 * Deepest leaf is now at depth log^2n from the root.
 * Find-set with no compression path travereses at deepest leaf, it has to go worst case through the giant ass tree

Total Cost: m * log^2n = O(mlogn)
